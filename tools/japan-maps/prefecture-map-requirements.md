# 都道府県移動地図 要件定義書

## 1. プロジェクト概要

### 1.1 プロダクト名（仮）
都道府県移動地図

### 1.2 コンセプト
**都道府県を、つまんで置くことができます。**

47都道府県から1種類を選び、その都道府県の形を日本地図上の別の場所へ、実際の縮尺を変えずに移動・回転・複製できるブラウザアプリとする。

数値で面積を説明するのではなく、実際の形を別の地域に重ねることで、都道府県の大きさ・形・距離感を直感的に理解できる「地図のおもちゃ」を目指す。

---

## 2. 目的

- 都道府県の大きさを直感的に比較できる体験を提供する
- 説明を読まなくても、触るだけで使い方が分かるUIにする
- 完成した配置を画像としてSNSで共有できるようにする
- WordPressサイト内または同一ドメイン配下に、静的Webアプリとして設置できるようにする
- サーバー、データベース、ログインを必要としない小さな構成にする

---

## 3. MVPの範囲

### 3.1 MVPに含める機能

1. 日本地図の表示
2. 47都道府県から1種類を選択
3. 選択した都道府県を地図上へ追加
4. ドラッグによる移動
5. 自由回転
6. 同じ都道府県の複製
7. 複数ピースの個別移動・個別回転
8. ピースの個別削除
9. 全消去
10. 直前操作の取り消し
11. PNG画像生成
12. Web Share APIによる共有
13. 共有非対応時のPNG保存
14. PC・スマートフォン対応
15. 完全クライアントサイド動作

### 3.2 MVPに含めない機能

- 複数種類の都道府県を同時に選ぶ
- 都道府県ピースの拡大・縮小
- 世界地図への配置
- 市区町村単位の選択
- ユーザー登録
- クラウド保存
- 公開ギャラリー
- コメント・いいね
- サーバー側画像生成
- SNSごとの専用投稿API連携
- 面積ランキングや統計表示
- ゲーム・クイズ機能
- 広告管理機能
- アクセス解析以外のサーバー処理

## 4. 基本ルール

### 4.1 選択ルール

- 一度に選択できる都道府県の種類は1種類だけとする
- 選択中の都道府県を変更する場合、配置済みピースが存在するときは確認ダイアログを表示する
- 確認文言例：
  - 「配置中の北海道をすべて削除して、長野県に変更しますか？」
- 「変更する」で既存ピースを全削除し、新しい都道府県に切り替える
- 「キャンセル」で現在の状態を維持する

### 4.2 複製ルール

- 同じ都道府県のピースは複数作成できる
- 各ピースは独立して移動・回転・削除できる
- ピース数の上限はMVPでは20個とする
- 20個を超えて追加しようとした場合は、追加できない旨を表示する

### 4.3 縮尺ルール

- 都道府県ピースの拡大・縮小は禁止する
- ピースの形状に対して許可する変形は、平行移動と回転のみとする
- CSS transformまたはSVG transformで `translate` と `rotate` のみを使用する
- `scale` は使用しない
- 背景地図と都道府県ピースは同じ投影法・同じ座標系から生成する
- ピースを移動しても再投影しない
- これにより、画面上のピースの大きさを固定する

### 4.4 回転ルール

- 回転角は0〜359.9度の範囲で自由に設定できる
- 1度単位にスナップさせない
- 内部値は小数を許容する
- 回転中心は、都道府県形状全体の表示上の中心とする
- GeoJSONの重心ではなく、投影後SVG形状のバウンディングボックス中心を基本とする
- 複数の島を含む都道府県は、すべての構成ポリゴンを1グループとして回転する

## 5. 想定ユーザー

- 地理や旅行が好きな人
- 北海道や岩手県などの広さを他地域と比べたい人
- 子どもと一緒に地図で遊びたい家庭
- SNSへ面白い比較画像を投稿したい人
- 授業やプレゼンで直感的な地理比較を見せたい人

## 6. 主要ユーザーストーリー

### US-01 都道府県を選ぶ
ユーザーは47都道府県一覧から北海道を選び、北海道のピースを地図上に表示できる。

### US-02 つまんで移動する
ユーザーは表示された北海道をドラッグし、関東地方の上へ移動できる。

### US-03 回転する
ユーザーは選択した北海道の回転ハンドルを操作し、任意の角度へ回転できる。

### US-04 複製する
ユーザーは北海道を複製し、複数の北海道を東日本へ並べられる。

### US-05 個別編集する
ユーザーは複数配置した北海道のうち、任意の1個だけを移動・回転・削除できる。

### US-06 画像にする
ユーザーは完成した配置を、操作UIを除いた1枚のPNG画像として生成できる。

### US-07 SNSへ共有する
対応端末では、生成したPNGを共有シートからSNSアプリ等へ渡せる。

## 7. 画面構成

## 7.1 全体レイアウト

### PC

- 上部：ヘッダー
- 左または上部：操作パネル
- 中央：日本地図キャンバス
- 下部：簡単な操作説明、クレジット

### スマートフォン

- 上部：アプリ名、都道府県選択
- 中央：地図キャンバス
- 下部：固定操作バー
- 詳細操作はボトムシートまたは折りたたみメニューに格納

## 7.2 ヘッダー

表示項目：

- アプリ名
- 短い説明文
- ヘルプ
- リセット

説明文候補：

> 都道府県を選んで、つまんで、好きな場所へ置いてみよう。

## 7.3 操作パネル

必須UI：

- 都道府県選択
- 「追加」
- 「複製」
- 「削除」
- 「1つ戻す」
- 「すべて消す」
- 「画像にする」
- 「共有」

状態に応じて無効化する：

- ピース未選択時：「複製」「削除」は無効
- 履歴なし：「1つ戻す」は無効
- ピースなし：「画像にする」「共有」は無効

## 7.4 地図キャンバス

- 日本全体が初期表示で収まる
- 都道府県境界線を表示する
- 背景地図は淡色にする
- 配置ピースは背景より目立つ表示にする
- 選択中ピースのみ、枠線・回転ハンドル・選択状態を表示する
- 非選択ピースには編集ハンドルを表示しない
- 操作UIと地図は視覚的に分離する

## 8. 操作仕様

## 8.1 ピースの選択

- ピース本体をクリックまたはタップすると選択状態になる
- 別のピースを選ぶと、以前の選択は解除される
- 地図の空白部分をクリックまたはタップすると選択解除する
- 重なっている場合は、最前面のピースを選択する
- 選択したピースは最前面へ移動する

## 8.2 ドラッグ移動

### PC

- マウス左ボタンでピースを押下
- 押下したまま移動
- ボタンを離した位置へ配置

### スマートフォン

- 1本指でピースを押下
- 指を動かして移動
- 指を離した位置へ配置

### 共通

- ドラッグ開始時のピース位置とポインター位置の差を維持する
- ドラッグ中にピースが指やマウスから飛ばないこと
- キャンバス外へ完全に消えないよう、最低限の一部が画面内に残る制約を設ける
- 移動完了時に履歴へ1操作として記録する
- `pointermove` ごとに履歴を追加しない

## 8.3 回転

- 選択中ピースの外周に回転ハンドルを1つ表示する
- ハンドルをドラッグすると、中心点を基準に回転する
- スマートフォンでも1本指で回転ハンドルを操作できる
- 回転中は現在角度を小さく表示してよい
- 回転完了時に履歴へ1操作として記録する
- 補助機能として、角度入力・角度スライダーはMVPでは設けない
- 2本指回転はMVPでは実装しない

## 8.4 追加

- 都道府県選択直後に最初の1個を自動追加してよい
- 以後「追加」を押すと、同じ都道府県をキャンバス中央付近に追加する
- 新規追加ピースは選択状態にする
- 既存ピースと完全に重ならないよう、追加ごとに少し位置をずらす
- 初期角度は0度とする

## 8.5 複製

- 選択中ピースの位置と回転角を引き継ぐ
- 複製後は右下へ一定量ずらす
- 複製されたピースを選択状態にする

## 8.6 削除

- 選択中ピースを削除する
- 削除後は選択なしとする
- キーボードのDeleteまたはBackspaceでも削除可能にしてよい
- テキスト入力中はキーボード削除を発火させない

## 8.7 すべて消す

- 配置ピースが存在する場合のみ確認ダイアログを表示する
- 都道府県の選択状態は維持し、ピースだけを全削除する

## 8.8 1つ戻す

対象操作：

- 追加
- 複製
- 移動
- 回転
- 削除
- 全消去
- 都道府県変更

- 最低20操作まで履歴を保持する
- やり直し機能はMVP対象外

## 8.9 背景地図の操作

- MVPでは背景地図のパン・ズームは実装しない
- 日本全体を固定表示する
- 画面幅に応じて地図全体をレスポンシブに拡大・縮小してよい
- 背景とピースを同じSVG viewBox内に配置し、画面リサイズ時は全体を同率で表示する
- ユーザー操作によるピース単体の拡大・縮小は禁止する

## 9. 地理データ仕様

## 9.1 データ形式

- 47都道府県の境界データをGeoJSONで保持する
- アプリ実行時にローカルファイルから読み込む
- 外部地図APIへアクセスしない
- データは必要に応じて事前簡略化する
- データの出典・ライセンスをREADMEと画面下部に明記する

## 9.2 投影法

要件：

- 背景地図と都道府県ピースを同じ投影法で生成する
- 日本列島の表示に適した投影法を使用する
- 実装候補は、日本中心の円錐図法とする
- 例：d3-geo の `geoConicConformal` または同等の投影法
- 中央経線・標準緯線は日本列島全体の歪みが小さくなる値を設定する
- Web Mercatorを無条件に採用しない
- 投影処理は初期データ生成時または起動時に一度だけ行う
- 移動時には投影し直さず、投影済みパスを平行移動・回転する

## 9.3 離島・複数ポリゴン

- MultiPolygonを正しく扱う
- 北海道の周辺島嶼、東京都の島嶼、沖縄県の離島などをデータから削除しない
- 同一都道府県のすべてのポリゴンを1つのSVGグループとして扱う
- 島同士の相対位置を保持する
- 当たり判定はバウンディングボックスだけでなく、可能な限り実形状に対して行う
- 実形状の当たり判定が難しい場合でも、クリック可能領域が極端に不自然にならないようにする

## 9.4 データ軽量化

- 表示上不要な細かすぎる頂点は簡略化する
- 47都道府県合計の転送サイズは、gzip後1MB以下を目標とする
- 海岸線の見た目を大きく損なわない
- 簡略化前データと簡略化処理をリポジトリに残すか、再生成手順をREADMEへ記載する

## 10. 状態管理

## 10.1 アプリ状態

最低限、以下を保持する。

```ts
type PrefectureId = string;

type Piece = {
  id: string;
  prefectureId: PrefectureId;
  x: number;
  y: number;
  rotation: number;
  zIndex: number;
};

type AppState = {
  selectedPrefectureId: PrefectureId | null;
  selectedPieceId: string | null;
  pieces: Piece[];
};
```

## 10.2 座標

- `x`, `y` はSVG viewBox座標で保持する
- DOMピクセル座標で永続化しない
- 画面サイズ変更後も相対配置を維持する
- 回転角は度数法で保持する

## 10.3 一時保存

- 現在の状態をlocalStorageへ自動保存する
- ページ再読み込み時に前回状態を復元する
- 初回起動時は空の状態にする
- データ形式にバージョン番号を持たせる
- 復元不能な古いデータは破棄し、アプリを正常起動する

例：

```ts
type SavedState = {
  version: 1;
  savedAt: string;
  state: AppState;
};
```

## 11. 画像生成仕様

## 11.1 出力内容

PNGに含める：

- 背景の日本地図
- 配置した都道府県ピース
- アプリ名または短いロゴ
- 選択中の都道府県名
- 任意の短い説明
- サイトURLまたはドメイン表記

PNGに含めない：

- ボタン
- セレクトボックス
- 回転ハンドル
- 選択枠
- デバッグ情報
- 操作用ガイド

## 11.2 出力サイズ

- 基本出力：1200 × 1200px
- SNSで見やすい正方形をMVPの標準とする
- 背景色は白またはサイトデザインに合わせた単色
- 高DPI端末でも文字や線がぼやけないよう、SVGからCanvasへ高解像度描画する
- 透過PNGはMVP対象外

## 11.3 生成方法

- SVGを複製し、操作UI用要素を除去する
- 必要なスタイルをインライン化する
- SVGをCanvasへ描画する
- CanvasからPNG Blobを生成する
- 外部画像を使用する場合はCORS問題が起きない構成にする
- 原則としてローカルSVG・フォント・CSSだけで生成する

## 11.4 出力ファイル名

形式：

`prefecture-map-{都道府県英字slug}-{YYYYMMDD-HHmm}.png`

例：

`prefecture-map-hokkaido-20260710-1030.png`

## 12. 共有仕様

## 12.1 Web Share API

- `navigator.share` とファイル共有対応を判定する
- 対応時はPNG Fileを共有する
- 共有テキスト例：

> 北海道をつまんで、別の場所に置いてみました。  
> 都道府県移動地図

- 共有URLとしてアプリのトップURLを含める

## 12.2 フォールバック

優先順位：

1. PNGファイル共有
2. PNG保存
3. アプリURLをクリップボードへコピー

- 共有非対応をエラー扱いにしない
- 「このブラウザでは画像共有に対応していないため、画像を保存しました」など、次の行動が分かる表示にする

## 12.3 状態付きURL

- MVPでは配置状態をURLに埋め込む機能は必須としない
- 将来拡張として、URL hashへ圧縮した状態を保存する方式を検討する
- サーバーへ状態を送信しない

---

## 13. レスポンシブ・モバイル要件

- 最小対応幅：320px
- iPhone Safari、Android Chromeを主要対象とする
- `touch-action` を適切に設定し、ドラッグ中にページが意図せずスクロールしないようにする
- 地図以外の領域では通常スクロール可能とする
- 操作ボタンのタップ領域は最低44 × 44pxを目安とする
- 回転ハンドルは指で掴める大きさにする
- スマートフォン縦向きを基本とする
- 横向きでも壊れないこと
- 画面回転後もピース位置を維持する

---

## 14. アクセシビリティ

- 都道府県選択にlabelを付ける
- ボタンに明確な日本語ラベルを付ける
- アイコンだけのボタンにはaria-labelを付ける
- キーボードで主要ボタンへ移動できる
- 選択中ピースをDeleteキーで削除できる
- 色だけに依存して選択状態を表現しない
- コントラストを確保する
- 動きを減らすOS設定が有効な場合、不要なアニメーションを抑制する
- エラー・完了通知はスクリーンリーダーへ伝わる領域で表示する

## 15. デザイン方針

- 子ども向け教材に寄せすぎない
- 専門的なGISツールに見せない
- 触りたくなる、軽い、余白のあるデザイン
- 使い方の長文説明を最初に出さない
- 初回だけ、3ステップの短いガイドを表示してよい

ガイド例：

1. 都道府県を選ぶ
2. つまんで動かす
3. 回して、増やして、画像にする

- 地図とピースの色はCSS変数で変更可能にする
- WordPressサイトのデザインに合わせやすい構成にする
- 日本語Webフォントは必須としない
- OS標準フォントを優先し、表示速度を重視する

## 16. 技術要件

## 16.1 推奨構成

- Vite
- TypeScript
- SVG
- d3-geo
- Vanilla TypeScript、または軽量なUIフレームワーク

### 優先順位

1. 保守しやすい
2. 依存が少ない
3. 静的ビルド可能
4. SVG操作が明確
5. Codexがテストを書きやすい

Reactを使う場合でも、状態管理ライブラリは原則追加しない。

## 16.2 配置

- `npm run build` で静的ファイルを生成する
- `dist` 配下を任意の静的ホスティングへ配置できる
- サブディレクトリ配信に対応する
- 例：`https://example.com/tools/prefecture-map/`
- Viteのbase pathを環境変数または設定で変更できる

## 16.3 ブラウザ対応

主要対象：

- 最新2世代のChrome
- 最新2世代のEdge
- 最新2世代のFirefox
- 最新2世代のSafari
- iOS Safari
- Android Chrome

Internet Explorerは対象外。

## 16.4 セキュリティ・プライバシー

- ユーザーの配置データを外部送信しない
- 外部APIを使用しない
- localStorage以外へ個人データを保存しない
- 入力された自由文はMVPに存在しない
- 依存ライブラリを最小化する
- `npm audit` で重大な既知脆弱性がない状態を目標とする
- CSPを設定しやすい構成にする

---

## 17. パフォーマンス要件

- 初回表示時、通常回線で操作可能になるまで3秒以内を目標とする
- 主要JavaScript bundleはgzip後200KB以下を目標とする
- 地理データはgzip後1MB以下を目標とする
- 20ピース配置時でもドラッグが実用上滑らかであること
- ドラッグ・回転処理は `requestAnimationFrame` を利用してよい
- 連続操作中に不要なDOM再生成を行わない
- 画像生成中は進行中表示を出し、二重実行を防ぐ

---

## 18. エラー処理

想定するエラー：

- GeoJSON読み込み失敗
- データ形式不正
- PNG生成失敗
- Web Shareキャンセル
- Web Share失敗
- localStorage使用不可
- localStorageデータ破損
- ピース上限超過

方針：

- 画面全体を白紙にしない
- ユーザーが次に取る行動を示す
- Web Shareのユーザーキャンセルは警告表示しない

## 24. Codexへの実装指示

1. まず要件を読み、曖昧点を `ASSUMPTIONS.md` に列挙する
2. 実装前に短い実装計画を `PLAN.md` に作成する
3. Phase 1から実装する

8. MultiPolygonを省略しない
9. 各主要機能にテストを書く
10. テストとビルドが通る状態まで修正する
11. 実装後、要件ごとの対応状況を `IMPLEMENTATION_STATUS.md` に記録する
12. 未実装項目・制約・既知問題を隠さず記載する
13. 地理データのライセンスを確認できない場合、仮データで進めず、データ差し替え可能な構造だけを実装する
14. 不要な依存ライブラリを追加しない
15. 完成後、ローカルで操作確認できる起動手順を提示する
